# Генератор черновиков карточек товаров

Прототип сервиса для B2B-интернет-магазина контрольно-измерительных приборов. Сервис принимает данные о приборе через форму или JSON, передаёт их в модель Google Gemini и возвращает черновик карточки товара для менеджера.

## Что получает на выходе

- SEO-заголовок до 70 символов.
- SEO-описание 800–1200 символов. Если сведений недостаточно, вместо текста указывается причина.
- Ключевые характеристики, перенесённые из исходных данных дословно.
- От 3 до 5 поисковых запросов.
- Блок для менеджера: для кого подходит прибор и какие задачи решает.
- Список «Что нужно уточнить» с пропущенными или неполными данными.

Там, где данных нет, модель пишет «данных нет». Она не должна придумывать характеристики, производителя, сертификаты и области применения.

## Технологии

- **Node.js 20+** (проверено на Node.js 22) — среда выполнения, ES-модули.
- **Express 5** — HTTP-сервер и маршруты API, раздача статических файлов.
- **dotenv** — загрузка настроек из файла `.env`.
- **Google Gemini API (модель `gemini-2.5-flash`)** — генерация черновика. Вызывается напрямую через встроенный `fetch`, отдельный SDK не нужен.
- **node:test** — встроенный модуль тестирования.
- **HTML, CSS и JavaScript без сборки** — интерфейс в папке `public/`.

## Требования

- Node.js версии 20 или новее: [nodejs.org](https://nodejs.org/).
- Ключ Google Gemini API. Его можно получить в [Google AI Studio](https://aistudio.google.com/apikey).

## Установка и запуск

1. Скачайте проект или склонируйте репозиторий:

   ```bash
   git clone https://github.com/Lalka00pq/AI_Assistant_for_Product_Descriptions
   cd AI_Assistant_for_Product_Descriptions
   ```

2. Установите зависимости:

   ```bash
   npm install
   ```

3. Создайте файл настроек из примера:

   ```bash
   cp .env.example .env
   ```

   На Windows используйте `copy .env.example .env`.

4. Откройте `.env` и вставьте свой ключ:

   ```
   GEMINI_API_KEY=ваш_ключ
   ```

5. Запустите сервер:

   ```bash
   npm start
   ```

6. Откройте в браузере адрес [http://localhost:3000](http://localhost:3000).

Для разработки можно использовать `npm run dev`: сервер перезапускается при изменении файлов в `src/` и `server.js`.

Если порт 3000 занят, укажите другой в `.env`, например `PORT=3100`.

## Настройки

| Переменная       | Обязательна | По умолчанию       | Назначение                                      |
|------------------|-------------|--------------------|-------------------------------------------------|
| `GEMINI_API_KEY` | да          | —                  | Ключ доступа к Gemini API                       |
| `GEMINI_MODEL`   | нет         | `gemini-2.5-flash` | Модель Gemini                                   |
| `PORT`           | нет         | `3000`             | Порт локального сервера                         |

Файл `.env` не попадает в Git (указан в `.gitignore`). Ключ нигде не записан в коде.

Если `GEMINI_API_KEY` не задан, сервер всё равно запустится и выведет предупреждение. Кнопка генерации вернёт понятную ошибку.

### Частые проблемы

- **`Cannot find package 'dotenv'` или `express`.** Не установлены зависимости. Выполните `npm install` в папке проекта и запустите сервер снова.
- **`EADDRINUSE` (порт занят).** Укажите другой порт в `.env`, например `PORT=3100`.
- **Ошибка 502 или 400 от модели.** Проверьте `GEMINI_API_KEY` и `GEMINI_MODEL` в `.env`, затем перезапустите сервер: `.env` читается только при запуске.

## Использование

На главной странице две вкладки:

- **Заполнить формой.** Укажите название, производителя, описание и характеристики. Кнопки примеров заполняют форму готовыми данными: полным (манометр) и неполным (термометр).
- **Вставить JSON.** Вставьте данные в том же формате, что и в API (см. ниже).

После нажатия «Сгенерировать» появляется результат. Его можно просмотреть в виде карточки, Markdown или JSON и скопировать.

## Формат входных данных

```json
{
  "name": "Манометр DM 02",
  "manufacturer": "Манотомь",
  "description": "Манометр показывающий общетехнического назначения",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "присоединение": "G1/2",
    "класс точности": "1,5"
  }
}
```

- `name` и `manufacturer` обязательны и не могут быть пустыми.
- `description` и `specs` необязательны. Значения характеристик могут быть числами: они переводятся в текст.
- Не больше 50 характеристик. Описание и каждое значение характеристики не длиннее 5000 символов.

## API

Сервер отдаёт два маршрута. Все ответы в формате JSON.

### `GET /api/samples`

Возвращает примеры для кнопок интерфейса и ограничения полей.

### `POST /api/cards`

Тело запроса: JSON во входном формате выше.

Успешный ответ (`200`):

```json
{
  "card": { "seoTitle": "...", "seoDescription": "...", "keyCharacteristics": [], "searchQueries": [], "managerBlock": {}, "missingData": [] },
  "checks": { "seoTitle": { "length": 0, "ok": true }, "seoDescription": {}, "searchQueries": {} },
  "markdown": "..."
}
```

Ошибка:

```json
{ "error": "Текст ошибки на русском языке" }
```

Пример запроса:

```bash
curl -X POST http://localhost:3000/api/cards \
  -H "Content-Type: application/json" \
  -d '{"name":"Термометр биметаллический","manufacturer":""}'
```

### Ошибки API

| Статус | Когда возникает                                                              |
|--------|------------------------------------------------------------------------------|
| 400    | Некорректный JSON, тело не объект, пустые обязательные поля, неверный тип характеристик, слишком длинный текст или больше 50 характеристик |
| 404    | Неизвестный адрес внутри `/api`                                              |
| 413    | Тело запроса больше 200 КБ                                                   |
| 429    | Превышен лимит запросов к Gemini                                             |
| 500    | Не задан `GEMINI_API_KEY` или внутренняя ошибка сервера                      |
| 502    | Модель отклонила запрос (неверный ключ или модель), недоступна, вернула пустой или некорректный ответ |
| 504    | Модель не ответила за 60 секунд                                              |


## Как устроен промпт и защита от выдумок

Промпт хранится в `src/prompt.js`. В нём заданы правила:

1. Использовать только данные из запроса. Ничего не придумывать.
2. Характеристики переносить дословно, без пересчёта единиц и перефразирования.
3. Отсутствующие значения помечать как «данных нет».
4. Если сведений мало для описания 800–1200 символов, написать об этом в `missingData`, а не растягивать текст.
5. Перечислять в «Что нужно уточнить» всё, что важно для карточки и не указано во входных данных.

Дополнительно ответ модели проверяется кодом:

- Модель получает схему ответа (`responseSchema`) и отвечает в формате JSON.
- `src/card.js` проверяет типы полей и отбрасывает пустые элементы списков. Если структура не совпадает, ответ отклоняется с ошибкой 502.
- Длины заголовка, описания и количества запросов проверяются отдельно (`buildChecks`) и показываются в интерфейсе счётчиками.

Счётчики считают символы по кодовым точкам, поэтому кириллица считается правильно.

Важно: проверка длины и формата не гарантирует, что модель не исказила факты.

## Тесты

```bash
npm test
```

Тесты не обращаются к реальному Gemini. Вызов модели подменяется функцией, поэтому тесты работают без ключа и без интернета. Проверяются:

- входные данные: пустые поля, неверные типы, лимиты, приведение чисел;
- структура ответа модели и счётчики длины;
- ошибки Gemini: 429, 403, 500, сетевой сбой, превышение времени, пустой ответ, некорректный JSON;
- маршруты API: страница, примеры, корректный товар, некорректный JSON, пустые поля, 404, скрытие внутренних ошибок.

## Примеры результатов

Примеры реальных ответов модели будут добавлены после прогона с действующим ключом. Для проверки можно использовать две готовые записи из интерфейса: полные данные манометра и неполные данные термометра. Для термометра модель должна отметить нехватку сведений и не придумывать производителя.

## Ограничения

- Короткие входные данные дают короткое описание. Модель честно указывает это в списке «Что нужно уточнить», но текст не будет 800 символов, если сведений нет.
- Нет базы данных и истории: черновики не сохраняются, после обновления страницы результат теряется. Скопируйте нужное до закрытия.
- Нет загрузки PDF и паспортов приборов. Данные вводятся вручную или через JSON.
- Нет авторизации: сервис рассчитан на запуск на одном компьютере.
- Ответ модели может содержать ошибки. Проверка структуры не заменяет вычитку менеджером.
